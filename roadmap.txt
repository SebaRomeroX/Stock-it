PHASE 1 — SETUP  [DONE]  2026-10-10
--------------------------------------------------------------
What:
  - Project skeleton: index.html, css/styles.css, js/main.js
  - Mobile-first viewport + base styles, dark theme by default
  - roadmap.txt created (this file)

Decisions:
  - Stack: plain HTML + CSS + JS. Zero dependencies, no npm,
    no build step, no framework. Rationale: simplest possible
    toolchain, everything runs by opening index.html.
  - Modules: native ES modules (type="module"). Rationale:
    modularity without tooling. Requires serving over HTTP
    (e.g. `python3 -m http.server`) instead of file:// —
    accepted tradeoff.
  - Persistence: localStorage with JSON serialization.
    Rationale: zero deps, synchronous, enough for a small
    store. Escape hatch: switch storage.js to IndexedDB later
    without touching feature code (see storage contract below).
  - Theme: CSS custom properties, dark-first, light theme
    ready to add via [data-theme="light"].
  - Layout: single page, bottom navigation bar (thumb-reach),
    max-width container so it also looks OK on desktop.

Storage contract (storage.js):
  - load(key) -> parsed object or default
  - save(key, value) -> writes JSON
  - reset(key) -> removes key
  Feature modules never touch localStorage directly.

Next goal: Phase 2 — data layer (storage.js).

--------------------------------------------------------------
What: js/storage.js — load(key, fallback) / save(key, value) /

Decisions:
  - Feature modules never touch localStorage directly

PHASE 3 — PRODUCTS: ADD / LIST / QTY  [DONE]  2026-10-10
--------------------------------------------------------------
What:
  - js/products.js: add(name, qty), setQty(id, qty),
    adjustQty(id, delta), remove(id), list(), render()
  - Products tab: add form (name + qty, default 1) on top,
    product list below with −/qty/+ controls and delete (×)
  - Quantities clamp at 0; integers only
  - Full innerHTML re-render after each mutation
  - Delete asks for confirmation

Decisions:
  - Schema trimmed to { id, name, qty, createdAt, updatedAt }
    for now — sku, price, category deferred to the phase that
    needs them (Rationale: keep the first feature minimal).
  - Full list re-render instead of patching single rows.
    Rationale: simplest correct code; fine at small store
    scale (hundreds of rows). Revisit only if slow.
  - Validation in products.js (throws Error) so UI shows the
    message via a transient form error.
  - EscapeHtml on names before injecting into innerHTML
    (XSS-safe even though data is local).

Next goal: Phase 4 — inventory movements (history per product).

UI REFINEMENTS (incremental, between phases)
--------------------------------------------------------------
2026-10-12 | No-stock badge + sort to top  [DONE]
  - Products with qty === 0 render a red "No stock" pill next
    to the name and float to the top of the list.
  - Decisions:
    - Sorting happens at render time only; stored order is
      untouched (stable sort keeps original order within
      each group).
    - Row stays interactive at qty 0 (bump + to restock →
      badge disappears and row re-sorts on next render).
    - Replaced the old muted-name treatment: name stays
      readable, badge carries the signal.

2026-10-12 | Price + item/storage value  [DONE]
  - Products now carry a price: chip line 2 shows
    "$2.50 × 4 = $10.00" (tap to edit price via prompt);
    summary line under the list shows total storage value.
  - Schema: price added { ..., price } (cents-based math).
  - Decisions:
    - Money math done in cents (unit price × 100) at every
      total to avoid float drift; prices stored as decimals
      rounded to 2 dp.
    - Migration on read: stored products without price get
      price 0 (no write migration).
    - Currency = USD via Intl.NumberFormat, single CURRENCY
      constant in products.js — swap when Settings (Phase 7)
      lands.
    - Price editing = prompt() on the meta line for now;
      replace with a proper edit form in the CRUD phase.
    - Add form: [name] / [qty] [price] [Add], wraps on
      narrow screens.
